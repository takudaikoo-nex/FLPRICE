# 供花発注システム メール送信 セットアップ手順

> 方式: 既存のメールサーバー（SMTP）から Supabase Edge Functions 経由で送信
> 作成日: 2026-07-26

---

## 1. 送信するメール

| # | 種別 | 宛先 | タイミング | 送信のトリガー |
|---|---|---|---|---|
| 1 | 受注通知 | 自社（ファーストリーフ） | 注文が入った直後 | 公開サイトから自動 |
| 2 | 請求書 | お客様（発注者） | スタッフが内容を確認してから | 管理画面のボタン |
| 3 | 発注書 | 供花業者（1社固定） | 受付締切後に葬儀ごとまとめて | 管理画面のボタン |

発注書は**葬儀（＝故人）単位**で、その葬儀に入った全注文を1通にまとめて送ります。
商品ごとの合計本数と、設営順に並べた名札一覧が本文に入ります。キャンセル済みの注文は除外されます。

## 2. 接続情報（Google Workspace）

`first-leaf.jp` は Google Workspace のため、以下の値を使います。

| 項目 | 値 |
|---|---|
| SMTPホスト名 | `smtp.gmail.com` |
| ポート番号 | `465`（SSL） |
| `SMTP_TLS` | `true` |
| ユーザー名 | `kota_oishi@first-leaf.jp` |
| パスワード | **アプリパスワード**（下記参照） |
| 送信元アドレス | `kota_oishi@first-leaf.jp`（管理画面から設定） |

### アプリパスワードの取得（必須）

Googleアカウントの**通常のログインパスワードではSMTP認証できません**。16桁のアプリパスワードを発行します。

1. `kota_oishi@first-leaf.jp` でログインし、[Googleアカウント](https://myaccount.google.com/security) を開く
2. **2段階認証プロセス**を有効にする（未設定の場合。アプリパスワードの発行に必須）
3. [アプリパスワード](https://myaccount.google.com/apppasswords) を開く
4. アプリ名に `Supabase` などを入力して作成
5. 表示された16桁（`abcd efgh ijkl mnop`）を控える。**スペースは詰めても詰めなくても可**

> アプリパスワードの項目が出ない場合は、2段階認証が未設定か、Workspace管理者が組織全体で禁止しています。
> 後者の場合は管理コンソールでの許可が必要です。

> **パスワードはDBには保存しません。** Supabaseのシークレット（環境変数）に登録します。

## 3. Edge Function のデプロイ

Supabase CLI を使います。初回のみログインとリンクが必要です。

```bash
# ログイン（ブラウザが開きます）
npx supabase login

# プロジェクトに接続
npx supabase link --project-ref kbifluukpqhbjmhhvbgg

# SMTPの接続情報を登録
npx supabase secrets set \
  SMTP_HOSTNAME=smtp.example.co.jp \
  SMTP_PORT=587 \
  SMTP_USERNAME=info@example.co.jp \
  SMTP_PASSWORD='********' \
  SMTP_TLS=true

# 関数をデプロイ
npx supabase functions deploy send-order-mail
```

`supabase/config.toml` で `verify_jwt = false` を指定しています。公開サイト（未ログイン）から受注通知を呼ぶためで、
**請求書の送信は関数の中で管理画面のログインを検証しています**（未ログインでは401を返します）。

## 4. 管理画面での設定

`/admin` →「葬儀・発注受付」→「設定」で以下を入力します。

| 項目 | 用途 |
|---|---|
| 受注通知メール | 自社の受け取り先（カンマ区切りで複数可） |
| 業者名 / 業者のメールアドレス | 発注書の送信先 |
| 送信元メールアドレス / 表示名 | すべてのメールの From |
| 事業者名・郵便番号・住所・電話番号 | 請求書メールの末尾に記載 |
| インボイス登録番号 | 請求書メールに記載 |
| 支払期限（注文日から何日） | 請求書メールの支払期限の計算に使用 |
| お振込先 | 請求書メールにそのまま記載（改行可） |

---

## 5. 動作確認

1. `/admin` →「供花 受注一覧」→ 対象の注文を開く
2. **「内容を確認」** で請求書メールの件名と本文をプレビュー
3. 問題なければ **「請求書を送信」**
4. 送信後、一覧に「請求書送信済」が表示される

受注通知は、公開サイトで注文が完了した時点で自動送信されます。注文詳細の「自社への受注通知」欄で送信済みかどうかを確認できます。

発注書は「葬儀・発注受付」の一覧から送ります。各行に注文件数と発注書の送信状況が表示され、
**受付締切を過ぎてから「発注書を送信」**を押す運用です。内容を修正した場合は再送できます。

> 受注通知はブラウザから呼び出しているため、送信直後にブラウザが閉じられた場合など、ごく稀に送信されないことがあります。
> その場合は注文詳細で「未送信」のままになるので、気づける形にしてあります。確実性を上げるならDBトリガーからの送信に切り替えます。

---

## 6. 注意点

- **送信元アドレスの一致**: 「送信元メールアドレス」は `kota_oishi@first-leaf.jp`（SMTPのユーザー名と同じ）にしてください。Gmailは異なる送信元を拒否します。別アドレスで送りたい場合は、Gmail側でエイリアスとして認証済みである必要があります
- **迷惑メール対策**: Google Workspace利用中であればSPFは通常設定済みです。念のため、テスト送信後にGmail側の受信トレイ（迷惑メールフォルダでないこと）を確認してください
- **送信上限**: Google Workspaceの1日あたり送信上限は2,000通です。供花の運用量であれば問題ありません
- **請求書はメール本文のテキスト**です。PDF添付が必要な場合は別途対応します
- 請求書は**再送**できます。金額や名札を修正した場合は再送してください
